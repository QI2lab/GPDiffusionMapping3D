CPU-ONLY SIMPLIFICATION AFTER THE USER'S PERFORMANCE REVIEW

Decision
The user authorized removing GPU code unless a clear acceleration path justified
its complexity. Use the validated NumPy/Numba CPU float64 implementation.
This decision supersedes the GPU requirements in the original stage plan.

Evidence before removal (local revision 39c7eeb)
Isolated, warmed, sequential CPU/GPU full-inference measurements:
  2D, 100000 transitions, 36 inducing values, 100 production sweeps:
    CPU 40.0194 s; GPU 29.9972 s; GPU speedup 1.334x.
  3D, 20000 transitions, 125 inducing values, 1000 production sweeps:
    CPU 102.3449 s; GPU 97.8870 s; GPU speedup 1.046x.
  Small 2D, 1000 transitions, warmed sweep:
    CPU 0.00189 s; GPU 0.01492 s; GPU slower by about 7.9x.
GPU was available and scientifically validated on actual RTX3090 hardware.
Removal is a performance/maintenance decision, not a CUDA availability issue.

The GPU implementation already fused likelihood/positivity reductions and kept
bulk arrays resident. Its Python control loop still synchronized a scalar for
every dependent Metropolis proposal/block, with separate small matrix products
and accepted-state updates. In 3D each 125-coordinate sweep has 16 blocks.
Eliminating those round trips would require moving sequential acceptance and
random-number generation onto the device, with new CUDA implementation and
validation. That is a substantial project with an unmeasured speedup. Merely
increasing block size is not a justified shortcut: size 16 failed the declared
mixing criterion on the smooth field, whereas size 8 passed. No approximation,
precision change or weakened convergence criterion is introduced for speed.
These workload measurements do not establish performance for all larger inputs.

Changes
- Remove CuPy kernels, device array management, GPU samplers and float32 code.
- Remove the gpu extra/default dependency group and CUDA wheels from the local
  uv environment. Base scientific dependency versions are unchanged.
- CLI always runs CPU float64; remove --backend and --dtype switches.
- Keep existing computational CPU callers compatible. Explicit unsupported
  backend/precision values raise errors; there is no silent conversion.
- Retain CSV/Parquet, exact column mappings, physical units and elapsed times.
- Preserve original 2D proposals and repaired blocked-8 3D Metropolis inference,
  fixed production geometry/widths and additional discarded burn-in.
- Retire GPU-only tests/scripts. Transfer full four-chain convergence and
  125-coordinate block-geometry checks to tests/cpu, retaining independent
  posterior quadrature, Gaussian-density and simulated-physics oracles.
- Keep historical numerical results and figures in docs and raw local artifacts.
  Historical plot scripts only read those archives; they do not execute CUDA.
  The removed experiments are available from local Git revision 39c7eeb.
