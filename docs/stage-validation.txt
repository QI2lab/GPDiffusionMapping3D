Stage 1: incomplete, failed prerequisite mathematical consistency check
Read the paper's preprint methods (publisher full text was inaccessible):
https://www.biorxiv.org/content/10.1101/2024.02.27.582378v1.full
The interpolation and transformed proposal must describe the same field.
Existing code sets R=K+epsilon*mean(K)*I, W=B.T@inv(R), and initializes Ddata=W@D.
Its proposal updates Dnew=D+K[:,k]*delta, but Ddata_new=Ddata+B[k,:]*delta.
Direct recomputation is instead W@Dnew. Their discrepancy is
  (B.T - W@K)[:,k]*delta = epsilon*mean(K)*W[:,k]*delta.
This is nonzero with existing regularization, so CPU agreement cannot be an
independent correctness oracle. Reproducer: scripts/validate_incremental.py.
Controlled example: maximum discrepancy 0.0033222158577337346.
No tolerance was widened and no correction was silently applied.
The next numerical change must isolate and document a consistent regularized
representation in both CPU and GPU implementations, preserving the prior,
proposal correction, update order and annealing/adaptation.
